## 1. Root causes identified

Three independent failure modes, listed by severity:

### 1a. Wrong RevenueCat API key baked into the app (highest impact)

`SupaClient.swift:30` held `appl_CzEAtrNVYSafdHDIXAFTUOgIgAU` — a key belonging
to a different RC project (probably the older `vidsum` YouTube-summary app).
The Fitrater iOS app record on RC (`appe7c93e7665`) issues public key
`appl_XcRnJzmGqEityyPyHuMWRdaSWvV`. With the wrong key, the SDK asked the wrong
project for offerings, so no product IDs matched what StoreKit could fetch.

Fix committed: swapped the constant to the correct `appl_XcRn…` key. Verified
via `strings` on the Debug binary and by observing the paywall render prices
after reinstall.

### 1b. Substring product-matching bug (silently overcharged users, wrong prices)

`CreditsSheet.swift` mapped RC packages → pack tiles with
`p.storeProduct.productIdentifier.contains(spec.id)`. Because
`"fitrater_v2_credits_500"` is a **prefix** of `"fitrater_v2_credits_5000"`,
the Popular tile (`_500`) would silently pick up the Mega product (`_5000`) if
Mega's package was iterated first — showing Mega's price on the Popular tile.

The same bug lived in `RcBilling.swift` (`grantCreditsIfNeeded`): purchasing
Mega could grant only 500 credits instead of 5000, depending on dictionary
enumeration order.

Fix committed: both call sites changed to exact-equality comparison.
- `CreditsSheet.swift:216` → `p.storeProduct.productIdentifier == spec.id`
- `RcBilling.swift:139`   → `Supa.creditPackGrants[productId]` (dict lookup)

### 1c. IAP metadata gaps (why the ASC objects sat in MISSING_METADATA)

- Monthly subscription was missing a price for **Costa Rica (CRI)** — the only
  territory annual had that monthly didn't. Diagnosed by set-diff of the two
  subscriptions' `prices` relationships.
- All four consumables had localizations + price schedules + review screenshots
  but no `inAppPurchaseAvailability` relationship — Apple treats that as
  "not for sale" and refuses to move the state to READY_TO_SUBMIT.

Fixes committed:
- Added CRI price at customer $14.99 (tier 10152) for `fitrater_v2_monthly`.
- Created `inAppPurchaseAvailabilities` records for all 4 consumables spanning
  the full 175-territory list, with `availableInNewTerritories: true`.

### Attempted to add IAPs to review submission — API said no

**Open risk**: if Apple does not auto-bundle, IAPs will stay stuck in
READY_TO_SUBMIT after app approval and the paywall will error again. See §7.

## 4. Pricing pass — worst-case-safe economy

Session went through **three pricing regimes** for the credit packs:

| Regime      | Starter | Popular | Pro Pack | Mega   | Notes |
| ----------- | ------- | ------- | -------- | ------ | ----- |
| Original    | 100 cr  | 500 cr  | 1500 cr  | 5000 cr| Paywall showed wrong prices due to substring bug. |
| "3x credits"| 300 cr  | 1500 cr | 4500 cr  | 15000 cr| Loses money on Popular / Pro Pack / Mega if backend COGS ≥ $0.003/cr. |
| **Final (safe)** | **150 cr** | **500 cr** | **1200 cr** | **3000 cr** | ~55% margin at $0.005/cr worst case; ~72% at $0.003/cr. |

USA base prices (unchanged across regimes): `$1.99 / $6.99 / $14.99 / $39.99`.
Apple auto-equalizes → TR: `₺99.99 / ₺399.99 / ₺799.99 / ₺1999.99`.

Small Business Program assumed (85% proceeds). Per-credit economics
(final regime):

| Pack   | USA  | Proceeds/cr | Break-even COGS | Margin @ $0.005/cr COGS |
| ------ | ---- | ----------- | ---------------- | ----------------------- |
| Starter (150) | $1.99  | $0.01127 | $0.01127 | +$0.94 / pack |
| Popular (500) | $6.99  | $0.01188 | $0.01188 | +$3.44 / pack |
| Pro Pack (1200) | $14.99 | $0.01061 | $0.01061 | +$6.74 / pack |
| Mega (3000)     | $39.99 | $0.01133 | $0.01133 | +$18.99 / pack |

Subscriptions (`subMonthlyCap` / `subAnnualMonthlyCap` in `SupaClient.swift`):

- Monthly: **1,200 cr / month** — at $0.005/cr COGS = $6 cost vs ~$12.74
  proceeds → +$6.74/mo per subscriber.
- Annual: **750 cr / month** (9,000/yr, 7-day free trial) — $45/yr COGS vs
  proceeds depending on price → healthy margin.

Signup gift: **25 credits** (was 100). Rationale: `Score a look` costs 5 cr;
25 credits = 5 scores or 1 try-on + 1 A-vs-B — enough to prove value without
delaying the first paid pack. Assumed CAC ≈ $0.13/user at worst-case COGS.

**Unknown**: real backend COGS/credit. All numbers above are conditional on
that figure. Recommend calculating from the AI provider + Supabase bill
divided by monthly credit consumption before scaling marketing.

## 7. Open risks / things a human needs to check

1. **IAPs may not be reviewed with the app.** The ASC v1 API does not accept
   `inAppPurchase*` as an item type on `reviewSubmissionItems`. Apple's docs say
   IAPs in READY_TO_SUBMIT are auto-bundled on a first submission, but I could
   not verify that programmatically. If, after Apple reviews the app, the IAPs
   are still READY_TO_SUBMIT (not APPROVED), open ASC UI → each IAP → "Submit
   with Version" or "Submit for Review". Otherwise the paywall will fetch RC
   products that Apple hasn't approved and the same "offerings empty" error
   returns.
2. **`app_store_connect_vendor_number` is null** on the RC iOS app record. Not
   strictly required for offering fetch, but should be filled in so RC can
   pull financial reports.
3. **Backend COGS is a guess.** All pricing decisions assume a worst case of
   ~$0.005 per credit consumed. If real costs (OpenAI/Anthropic + Supabase +
   image gen) run higher, Popular / Pro Pack / Mega bleed. Compute actual
   spend ÷ credits consumed after a week of production traffic.
4. **Stale RC products.** RC still lists unused products (`credits_100`,
   `fitscore_credits_100/500/1500/5000`, `fitscore_pro_monthly`, plus the
   `Test Store` app). They are not in the current offering, so they don't
   break anything, but they clutter the dashboard. Archive when convenient.
5. **Sandbox testing not yet performed.** ASC → Users and Access → Sandbox
   → create a tester. On iPhone: Settings → App Store → Sandbox Account → sign
   in. Launch Fitrater → Credits → attempt a purchase. Expect prices to render
   and StoreKit to complete the transaction in sandbox mode.
6. **Turkish price mismatch was NOT a bug in ASC.** The paywall's
   "500 credits ₺1,299.99" earlier was the substring bug (§1b) showing Mega's
   price on the Popular tile. Verified ASC's actual TR mapping was
   ₺49.99/₺249.99/₺499.99/₺1299.99 for the pre-repricing tiers. Confused me for
   a minute; leaving the note so future-you doesn't chase Apple's tier tables.
7. **Screenshots are only in the 6.5″ slot** (`APP_IPHONE_65`, 1242×2688).
   The 6.7″ slot (`APP_IPHONE_67`, 1290×2796) still shows the older
   `1_home`…`6_tryon` set. Apple accepts both for iPhone; not blocking.
   If you want a consistent look, upload the same 6 shots at 1290×2796 to
   set `7d955704-eebe-481d-a33e-913b3172527d`.
