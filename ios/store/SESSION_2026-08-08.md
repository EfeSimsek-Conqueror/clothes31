### 1.3  Stylist Chat (new feature)
Moderate AI chat that replaces user-facing brutal roast entry.

- **UI**: `StylistChatView`, `StylistChatViewModel`, `StylistApi`,
  `StylistMessage`, `ChatChip`, `MessageBubble`, `StylistHomeInviteBar`
  — all appended to `App/MainTabView.swift` to avoid pbxproj edits.
- **Entry points**: Home invite bar ("Ask your stylist…") + Camera menu
  row ("Chat with Hem"). Both call `CameraMenuBus.shared.request(.chat)`.
- **Backend**: `supabase/functions/stylist-chat/index.ts` — Fal any-llm
  vision endpoint, model `google/gemini-2.5-pro`, reuses `FAL_KEY`
  secret (no extra vendor / no extra key). Nano Banana
  (`fal-ai/gemini-25-flash-image`) noted for future image-gen features.
  System prompt = short editorial stylist voice; per-msg image
  attachment supported (base64 field).
- **Fallback**: `StylistApi.send()` catches any error and returns a
  canned reply so the UI is usable before the edge function is deployed.
- **Memory backend**: `supabase/migrations/0005_stylist_memory.sql` —
  tables `chat_threads`, `chat_messages`, `outfit_memory`,
  `wardrobe_items`, `outfit_items` with pgvector + RLS +
  `match_outfit_memory(...)` RPC. **Not yet applied to the remote DB**
  (Supabase MCP was read-only during session; user needs to run migration).

### 1.6  Compose Cover fixes
`supabase/functions/compose-cover/index.ts`:

- **Face upscaler removed** — `upscaleSubject(...)` call replaced with a

### 1.8  Studio 2.0 — sequential outfit wizard
Biggest single change of the day. All code lives in
`Studio/StudioCreateView.swift` (append-only, no pbxproj edits).

**Gateway**:
- `StudioCreateGateway` — editorial "Compose a new look" screen with two
  modes: **MODE · 01 Single Piece** (routes to existing StudioCreateView)
  and **MODE · 02 Full Outfit** (routes to new `OutfitWizardView`) with
  a NEW badge and inked accent card.

**Outfit wizard** (`OutfitWizardView` + `OutfitWizardModel`):
- Phase 1 **Compose**: pick pieces from a grouped 3-col grid (Tops /
  Bottoms / One-piece & Outerwear / Footwear / Accessories). Free plan
  capped at 2 pieces per outfit; Pro upsell alert on 3rd tap.
- Phase 2 **Iterate**: for each selected slot, mount the full
  `StudioCreateView` with `presetType` + `presetSubtype` locked in
  Step 1 — the user gets the same guided-design questions the single
  piece flow asks (silhouette, sleeve, colors, fabric, etc), one
  piece at a time.
- Phase 3 **Combining**: full-screen `WaitingOverlay` with rotating
  tips while the two combine calls run.
- Phase 4 **Done**: swipeable full-width `TabView(.page)` with FRONT
  and SIDE renders + two-dot indicator.

**True multi-piece combine** (not compose-cover this time):
- `runCombine()` calls `Repo.generatePiece(...)` twice in parallel —
  one prompt asking for a front view, one for a side view.
- Prompt has a HARD RULES block: only the pieces provided, no invented
  garments, no accompanying clothing if a category was skipped, no
  magazine chrome (masthead / barcode / headline / price). Per-piece
  placement instructions cover accessories properly (bag held by
  strap, sunglasses hanging from neckline, hat held in hand,
  jewelry on joints, etc.) because the mannequin is headless.
- Both views persist to Journal: front as `outfit_studio`, side as
  `outfit_studio_side` (`linked_piece_id` points to the front).

**Subtype-specific questions in StudioCreateView**:
- New options: `NECKLINES`, `HOODIE_CLOSURES`, `HOODIE_DRAWSTRING`,
  `CARDIGAN_CLOSURES`, `BLAZER_LAPELS`, `BLAZER_BUTTONS`,
  `SHIRT_COLLARS`, `WAIST_RISES`, `PANT_FITS`.
- New wizard step IDs 20–28 (Neckline / Hoodie closure / Drawstring /
  Cardigan closure / Blazer lapel / Blazer buttons / Shirt collar /
  Pant fit / Waist rise).
- `applicableSteps(type:subtype:)` routes each subtype to just the
  extra steps that matter — T-shirt gets Neckline, Hoodie gets
  Closure + Drawstring, Cardigan gets Cardigan closure, Blazer gets
  Lapel + Buttons, Shirt gets Collar, Trousers/Jeans/Chinos get
  Fit + Waist rise.
- `WizardState` and `WizardSnapshot` extended with all the matching
  fields; `renderPrompt` weaves them into the default (non-shoes /
  non-accessory) branch so Fal actually renders those details.

**OutfitPiece enum expanded** (8 → 19 cases):
- Tops: `tshirt`, `shirt`, `hoodie`, `cardigan`, `blazer`
- Bottoms: `pants`, `jeans`, `shorts`, `skirt`, `sweatsuit`
- One-piece: `dress`
- Outerwear: `jacket`
- Footwear: `shoes`
- Accessories: `bag`, `sunglasses`, `belt`, `scarf`, `hat`, `jewelry`
- Each has: `emoji`, `closetCategory`, `subtypeHint`, `promptToken`,
  `presetType`, `displayName`, `group`, and — critically —
  `placementInstruction` which the combine prompt splats out per-piece
  so each item goes to the right spot on a headless mannequin.

**Step 1 lock (outfit mode)**:
- `StudioCreateView` now takes `presetSubtype: String?`. When both
  `presetType` and `presetSubtype` are set, Step 1's Type + Subcategory
  chips render as `LockableChip` with a lock icon on the active one
  and faded / non-hit-testing on the rest. Only "Add reference photo"
  is interactive on that step.

**Single-piece render prompt (v4)**:
- Reverted from the earlier "young stylish model" mistake back to a
  headless mannequin because the model was inventing accompanying
  garments (a jean-shorts + t-shirt when only a cardigan was asked).
- Prompt now explicitly requires: FULL BODY visible from shoulders
  to feet, both arms attached, standing upright, front-facing.
- Explicitly forbids any accompanying clothing / layered garments —
  "ONLY the <piece> is visible; bare mannequin surface everywhere else".

**From-closet composition**:
- Compose phase renders a **FROM YOUR CLOSET** horizontal strip above
  the piece picker. Signed URLs for the last 20 closet items; tap a
  tile → the OutfitPiece is inferred from subcategory → auto-added
  to the outfit + prefilled with that item.
- Each selected slot in the "ORDER" list is a tappable row. Tap → sheet
  filtered by both `closetCategory` and `subcategoryHint` (accessories
  MUST match subcategory, so Bag picker doesn't show Sunglasses).
- Prefilled slots are **skipped up-front** at the compose → iterate
  transition via `skipPrefilled()`, and again after every
  `advanceStep()`. If every slot is prefilled, the wizard jumps straight
  to `.combining`. Prevents the "blank Step 2" bug that happened when
  the old `Color.clear.onAppear { advanceStep(..) }` skip pattern raced
  the SwiftUI `.id(stepKey)` mount.
- Re-tap deselects: piece chips and closet strip tiles both toggle
  off on second tap, and also clear their `prefilled` entry.

**Journal detail — swipeable front/side**:
- `Score/ScoreDetailView` fetches the linked `outfit_studio_side`
  sibling via new `Repo.linkedOutfit(linkedTo:kind:)` helper when
  opening an `outfit_studio`. The hero becomes a `TabView(.page)` with
  a FRONT / SIDE dot indicator at the bottom.
- `Repo.outfits(limit:)` filters `outfit_studio_side` out of the
  general list so the Journal doesn't show duplicates.

**Pricing** (`Data/SupaClient.swift`, added by the background agent
sub-session, kept as-is):
- `singlePieceCost = 10`, `outfitTwoCost = 18`, `outfitThreeCost = 24`,
  `outfitFourCost = 32`, `outfitExtraPieceCost = 8` (per additional),
  `extraAlternativesCost = 5`, `singleAlternativeRegenCost = 2`,
  `studioCombineStandaloneCost = 6`, plus `Supa.outfitCost(pieceCount:)`.
